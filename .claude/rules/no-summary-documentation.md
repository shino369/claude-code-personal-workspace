# No Summary Documentation

**Do NOT create summary or documentation files unless explicitly requested.**

## Never Create These

- Summary files (e.g., `SUMMARY.md`, `CHANGES.md`, `WORK_SUMMARY.md`)
- Task completion reports or wrap-up documents
- README files explaining work performed
- Any markdown files describing "what Claude did"

Users can review work through conversation history, git commits, and `/logs/` audit logs.

## Only Create Documentation When

1. **User explicitly requests it**: "Create a README explaining this feature"
2. **Required for the project**: API docs, user guides, technical specs as deliverables
3. **Part of code**: Inline comments, JSDoc, function documentation

## Key Principle

**Just do the work, don't document that you did it.**
